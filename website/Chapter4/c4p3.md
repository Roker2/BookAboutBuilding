# Параграф 3: Обновление исходников в дереве

## Поиск изменений на GitHub

Поиск происходит так, что можно подсматривать изменения у других людей.

### Исходники для того же устройства

В поиск вбивается, к примеру, device_xiaomi_mido. Выдается список всех репозиториев, надо выбрать сортировку по "недавно обновленные", тогда будут показываться последние активные репозитории. Потом репозитории надо проанализировать и посмотреть, какие изменения могут быть по делу.

### Исходники для похожих устройств

Критерии похожести:

* устройства с тем же SoC, к примеру, tissot и mido, так как у них msm8953;

* устройства +- одного и того же поколения, к примеру, mido и santoni, которые имеют в целом похожие процессоры, msm8953 и msm8937 соответственно.

### Общие изменения

Такие изменения могут быть применены к большинству устройств. Следите за известными проверенными мейнтейнерами или прошивками, к примеру [LineageOS](https://github.com/LineageOS), можно найти много чего интересного!

## Qualcomm - CAF/CodeLinaro

Там можно найти обновления, которые применены под конкретный SoC. Как найти нужное дерево? Надо открыть любой CAF-тег манифеста под нужный ЦПУ, к примеру, [msm8953](https://git.codelinaro.org/clo/la/platform/manifest/-/blob/LA.UM.6.6.c32-10800-89xx.0/LA.UM.6.6.c32-10800-89xx.0.xml). Там видно, что нужное дерево лежит в репозитории [`platform/vendor/qcom/titanium_64`](https://git.codelinaro.org/clo/la/platform/vendor/qcom/titanium_64):

```xml
<project name="platform/vendor/qcom/titanium_64" path="device/qcom/msm8953_64" revision="9f0b6625657eb497854fb681a01d63acfda04c99" upstream="LA.UM.6.6.c32"/>
```

Далее просто сравниваете со своими исходниками или с предыдущим тегом, с которого были взяты изменения ранее.

Следить за релизами CAF можно [тут](https://t.me/CAFReleases).

## Как применять патчи

У нас уже есть замечательный инструмент - git, через который можно и нужно тянуть изменения.

Для начала добавим репозиторий, из которого надо подтянуть коммит:

```bash
git remote add any_repo_name url
git fetch any_repo_name branch
```

`branch` не обязателен, но в противном случае скачает информацию из всех веток репозитория, что, временами, не является хорошим и оптимальным решением.

Далее можно применять коммит:

```bash
git cherry-pick commit_sha
```

В случае, если все хорошо, коммит просто применится. В случае, если надо поправить что-то в названии, к примеру название устройства, то надо ввести команду `git commit --amend`, только учитывайте, что не должно быть что-то добавлено через `git add`, иначе эти изменения также применятся к коммиту.

Если есть конфликты, то надо их исправить, добавить файлы через `git add` и далее выполнить команду:

```bash
git cherry-pick --continue
```

Если надо откатить все к состоянию, как было, то надо выполнить эту команду:

```bash
git cherry-pick --abort
```

Не забудьте поменять в названии коммита кодовое имя устройства, если оно было!

## Изменения от производителя

С выходом новой прошивки, можно сделать дамп прошивки. Точно сказать, что можно обновить с помощью дампа в дереве устройства, сложно, так как это по большей части специфика. Можно к примеру обновить конфиги аудио, keylayouts, NFC-конфиги. Про дамп прошивки уже писалось в [параграфе 1](c4p1.md) этой главы. Потом просто сделать коммит:

```bash
git commit -m "codename: Update something from ROM build fingerprint"
```
